# Life OS — модель внешнего результата (на согласование)

Статус: проект модели, код и миграции намеренно не реализованы до согласования.

## Зачем разделять уровни

Текущая модель задачи хранит статус и доказательство рядом с задачей. Это подтверждает действие внутри Life OS, но само по себе не доказывает публикацию, внешний отклик или достижение цели. Предлагаемая модель хранит эти факты отдельно и не повышает уровень автоматически по одному текстовому доказательству.

## Уровни подтверждения

| Уровень | Код | Что подтверждено | Минимальные данные |
|---|---|---|---|
| 1 | `action_completed` | действие выполнено | задача, время фиксации |
| 2 | `artifact_created` | создан артефакт | тип артефакта, добровольно добавленное доказательство |
| 3 | `artifact_shared` | артефакт опубликован или отправлен | канал отправки, необязательная ссылка |
| 4 | `feedback_received` | получен внешний отклик | тип отклика, время; содержание — только по желанию |
| 5 | `goal_reached` | критерий цели достигнут | ссылка на цель и явное подтверждение пользователя |

Уровень монотонный только по подтверждённым событиям: Life OS не выводит `feedback_received` из факта публикации и не выводит `goal_reached` из наличия текста или файла.

## Предлагаемые типы данных

```ts
type ResultEvidenceLevel =
  | 'action_completed'
  | 'artifact_created'
  | 'artifact_shared'
  | 'feedback_received'
  | 'goal_reached';

type ArtifactKind = 'text' | 'link' | 'image' | 'file' | 'other';
type FeedbackKind = 'reply' | 'comment' | 'approval' | 'rejection' | 'metric' | 'other';

interface ResultArtifact {
  id: string;
  taskId: string;
  goalId?: string;
  kind: ArtifactKind;
  note?: string;       // локально; не отправляется в аналитику
  url?: string;        // локально; не отправляется в аналитику
  localAssetRef?: string;
  createdAt: string;
  sharedAt?: string;
  shareChannel?: 'direct' | 'public' | 'client' | 'team' | 'other';
}

interface ExternalFeedback {
  id: string;
  artifactId: string;
  kind: FeedbackKind;
  note?: string;       // локально; не отправляется в аналитику
  receivedAt: string;
}

interface ResultConfirmation {
  goalId: string;
  level: ResultEvidenceLevel;
  artifactIds: string[];
  feedbackIds: string[];
  confirmedByUser: boolean;
  confirmedAt: string;
}
```

Существующее `Task.proof` остаётся совместимым доказательством уровня 1 или 2 после явного выбора пользователя. Миграция не должна автоматически считать старый текст публикацией, откликом или достигнутой целью.

## Аналитические события

События включаются только после отдельного согласия. Личный текст, ссылки, названия целей, комментарии, причины срыва и содержимое артефактов не передаются.

| Событие | Триггер | Разрешённые свойства |
|---|---|---|
| `onboarding_started` | показ первого шага новому пользователю | `locale`, `app_version` |
| `goal_created` | цель сохранена | `horizon: week|month`, `source: onboarding|goals` |
| `day_built` | план дня сохранён | `task_count`, `source` |
| `focus_started` | таймер реально запущен | `duration_bucket`, `task_type` |
| `artifact_added` | пользователь сохранил артефакт | `artifact_kind`, `evidence_level` |
| `review_completed` | обязательные данные разбора сохранены | `outcome`, `has_correction`, `risk_direction` |
| `next_day_returned` | приложение открыто в следующий календарный день после завершённого разбора | `days_since_review` |

Правила реализации:

- транспорт аналитики по умолчанию выключен;
- согласие хранится локально и может быть отозвано;
- событие формируется через единый типизированный адаптер;
- при отсутствии провайдера события не покидают устройство;
- очередь не содержит пользовательский текст и очищается вместе со сбросом данных;
- идентификаторы задач, целей и артефактов не передаются внешнему провайдеру;
- события проверяются тестами на запрещённые свойства.

## Безопасная share-карточка

Пользователь вручную выбирает каждое поле:

- короткое название результата;
- уровень подтверждения;
- тип артефакта;
- дата;
- добровольно выбранная ссылка;
- нейтральная подпись Life OS.

Никогда не включаются: риск, надёжность, XP, серия, причины срыва, незакрытые обязательства, долги, личные комментарии, полный текст цели или данные профиля.

## Решения, которые нужно согласовать

1. Считать ли старое `Task.proof` уровнем 1 по умолчанию или просить пользователя классифицировать его.
2. Хранить ли изображения как локальные data URL/Blob или только ссылку на файл устройства.
3. Нужен ли внешний аналитический провайдер; до выбора провайдера реализация остаётся локальной и выключенной.
4. Должно ли достижение цели требовать хотя бы один артефакт уровня 2, или достаточно явного подтверждения пользователя.
